## 2026-07-13 — SQL: Use GENERATE SERIES to fill date gaps

Reports with gaps in time series confuse business users. Use GENERATE_SERIES (PostgreSQL/Synapse) or a calendar table to produce all dates, then LEFT JOIN your data — gaps show as 0 instead of missing rows.

```sql
-- Fill daily gaps for a 30-day report
WITH calendar AS (
  SELECT generate_series(
    DATE_TRUNC('day', NOW()) - INTERVAL '30 days',
    DATE_TRUNC('day', NOW()),
    INTERVAL '1 day'
  )::date AS report_date
)
SELECT c.report_date, COALESCE(SUM(s.amount), 0) AS total
FROM calendar c
LEFT JOIN sales s ON s.sale_date = c.report_date
GROUP BY c.report_date
ORDER BY c.report_date;
```

## 2026-07-15 — Data Quality: Use checksums to validate file transfers

When moving large files between storage accounts or cloud regions, always validate with MD5/SHA256 checksums. A corrupted file that passes row count checks but fails checksum is a silent data corruption risk.

```python
import hashlib

def file_checksum(path: str) -> str:
    h = hashlib.md5()
    with open(path, 'rb') as f:
        for chunk in iter(lambda: f.read(8192), b''):
            h.update(chunk)
    return h.hexdigest()

# Compare source and destination checksums
assert file_checksum(source) == file_checksum(dest), 'Checksum mismatch!'
```

## 2026-07-16 — PySpark: Use coalesce instead of repartition when reducing

When reducing partition count, `coalesce(n)` avoids a full shuffle by merging local partitions — much cheaper than `repartition(n)`. Use `repartition` only when you need even distribution or want to increase partitions.

```python
# Reducing partitions — use coalesce (no shuffle)
df.coalesce(10).write.parquet(output_path)

# Increasing partitions or redistributing — use repartition (full shuffle)
df.repartition(200, 'customer_id').write.parquet(output_path)
```

## 2026-07-18 — SQL: Materialized views for expensive aggregations

Repeatedly running the same GROUP BY aggregation on billions of rows is wasteful. Materialize it as a view or table and refresh on a schedule. Power BI and downstream queries read the pre-computed result.

```sql
-- Synapse Analytics / Dedicated SQL Pool
CREATE MATERIALIZED VIEW gold.mv_monthly_sales
WITH (DISTRIBUTION = HASH(customer_id))
AS
SELECT
  DATE_TRUNC('month', sale_date) AS month,
  customer_id,
  SUM(amount) AS total_sales
FROM silver.sales
GROUP BY DATE_TRUNC('month', sale_date), customer_id;
```

## 2026-07-21 — PySpark: Filter before join, not after

Always apply `.filter()` on DataFrames before joining them. Spark pushes filters down, but explicit pre-filtering reduces shuffle size and speeds up joins significantly.

```python
# Good — filter first, then join
active = customers.filter(col('status') == 'active')
result = orders.join(active, 'customer_id')

# Bad — filters after join
result = orders.join(customers, 'customer_id').filter(col('status') == 'active')
```

## 2026-07-22 — SQL: Use window functions instead of self-joins

Self-joins to compute running totals or previous values are slow and hard to read. Replace them with window functions — they run in a single pass over the data.

```sql
-- Running total per customer
SELECT customer_id, amount,
  SUM(amount) OVER (
    PARTITION BY customer_id
    ORDER BY transaction_date
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_total
FROM transactions;
```

## 2026-07-23 — Azure Data Factory: Use watermark tables for incremental loads

Never do full-table reloads for large sources. Store the last successful load timestamp in a control table and use it as a filter in your source query. This reduces data transfer by 95%+ on mature pipelines.

```sql
-- ADF source query
SELECT * FROM dbo.Sales
WHERE updated_at > '@{activity('GetWatermark').output.firstRow.last_ts}'
  AND updated_at <= '@{utcNow()}'
```

## 2026-07-24 — Delta Lake: Time travel for safe backfills

Before a risky backfill, note the current Delta version with `DESCRIBE HISTORY`. If the backfill goes wrong, restore with `RESTORE TABLE ... TO VERSION AS OF N` — no need for a backup restore.

```sql
-- Check current version before backfill
DESCRIBE HISTORY delta.`/mnt/gold/fact_sales`;

-- Restore if something goes wrong
RESTORE TABLE delta.`/mnt/gold/fact_sales` TO VERSION AS OF 42;
```

## 2026-07-25 — PySpark: Avoid Python UDFs — use native Spark functions

Python UDFs serialize data to Python, process row-by-row, and serialize back. Native Spark functions (`pyspark.sql.functions`) run in the JVM and can be 10–100x faster. Use `pandas_udf` when you truly need Python logic.

```python
# Bad — Python UDF (slow)
@udf(StringType())
def upper(s): return s.upper() if s else None

# Good — native function (fast)
from pyspark.sql.functions import upper
df.withColumn('name', upper(col('name')))
```

## 2026-07-26 — SQL: CTEs improve readability and performance

Common Table Expressions (CTEs) make complex queries readable and allow the optimizer to reuse subquery results. In most modern engines, a CTE referenced once is inlined; referenced twice, it may be materialized.

```sql
WITH monthly_sales AS (
  SELECT DATE_TRUNC('month', sale_date) AS month,
         SUM(amount) AS total
  FROM sales
  GROUP BY 1
),
ranked AS (
  SELECT *, RANK() OVER (ORDER BY total DESC) AS rnk
  FROM monthly_sales
)
SELECT * FROM ranked WHERE rnk <= 3;
```

## 2026-07-28 — PySpark: Cache DataFrames used more than twice

If you read the same DataFrame in 3+ actions (count, write, join), call `.cache()` after first creation. Spark recomputes lineage from scratch on every action otherwise. Unpersist when done to free memory.

```python
silver_df = transform(bronze_df).cache()

row_count = silver_df.count()          # action 1 — reads from cache
silver_df.write.delta.save(path)       # action 2 — reads from cache
silver_df.join(dim_df, 'id').show()    # action 3 — reads from cache

silver_df.unpersist()
```
