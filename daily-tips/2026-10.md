# Daily Data Engineering Tips — October 2026


## 2026-10-01 — SQL: Index foreign key columns in fact tables

Fact tables join to dimensions on foreign keys. Without indexes on those columns, every join does a full table scan. Add non-clustered indexes on all FK columns in your fact tables.

```sql
-- SQL Server / Azure SQL
CREATE NONCLUSTERED INDEX IX_fact_sales_customer
  ON dbo.fact_sales (customer_id)
  INCLUDE (amount, transaction_date);

CREATE NONCLUSTERED INDEX IX_fact_sales_product
  ON dbo.fact_sales (product_id)
  INCLUDE (amount, quantity);
```

## 2026-10-03 — Data Quality: Use Great Expectations for automated data contracts

Define data expectations as code — column types, value ranges, referential integrity. Run them in your pipeline as a quality gate. Failed expectations block the write and alert the team before bad data reaches consumers.

```python
import great_expectations as gx

context = gx.get_context()
suite = context.add_expectation_suite('silver.sales')
suite.add_expectation(
    gx.expectations.ExpectColumnValuesToBeBetween(
        column='amount', min_value=0, max_value=1_000_000
    )
)
```

## 2026-10-05 — Delta Lake: Enable Change Data Feed for incremental reads

Delta's Change Data Feed (CDF) tracks row-level inserts, updates, and deletes. Use it to propagate only changed records downstream instead of reprocessing entire tables.

```sql
-- Enable on existing table
ALTER TABLE silver.customers
SET TBLPROPERTIES ('delta.enableChangeDataFeed' = 'true');

-- Read changes since version 10
SELECT * FROM table_changes('silver.customers', 10)
WHERE _change_type IN ('insert', 'update_postimage');
```

## 2026-10-06 — SQL: Partition elimination is your best optimization

Filtering on a partition column eliminates entire file groups before reading. A query on a 10TB table with date partitioning might read only 27GB for a single month. Always design partition keys around your most common query patterns.

```sql
-- Table partitioned by year, month
-- This query reads ONLY 2024/01 partition files
SELECT SUM(amount)
FROM fact_sales
WHERE year = 2024 AND month = 1;
```

## 2026-10-08 — Data Quality: Reconcile row counts between source and target

After every load, compare row counts between source and destination. A mismatch signals a dropped partition, a failed partial write, or a filter bug. Log the delta and alert on >0.1% variance.

```python
def reconcile(source_count: int, target_count: int, table: str) -> None:
    delta = abs(source_count - target_count)
    pct = delta / source_count if source_count > 0 else 1.0
    if pct > 0.001:
        raise ValueError(
            f'{table}: source={source_count:,}, target={target_count:,}, '
            f'delta={delta:,} ({pct:.2%}) — exceeds 0.1% threshold'
        )
```

## 2026-10-09 — PySpark: Handle skewed joins with salting

When one join key has millions of rows (e.g., a 'null' customer_id), that partition becomes a hotspot. Salt the key by adding a random suffix 0–N, replicate the other side N times, then join and remove the salt.

```python
import random
from pyspark.sql.functions import col, lit, concat, rand, floor

N = 10  # salt factor
salted_fact = fact.withColumn('salt', (rand() * N).cast('int'))\
                   .withColumn('join_key', concat(col('customer_id'), lit('_'), col('salt')))

exploded_dim = dim.crossJoin(
    spark.range(N).withColumnRenamed('id', 'salt')
).withColumn('join_key', concat(col('customer_id'), lit('_'), col('salt')))

result = salted_fact.join(exploded_dim, 'join_key').drop('salt', 'join_key')
```

## 2026-10-11 — SQL: Use EXCEPT and INTERSECT for data reconciliation

EXCEPT and INTERSECT are powerful for reconciliation — find rows in source but not target, or rows that match exactly. Much faster than a NOT EXISTS correlated subquery on large tables.

```sql
-- Rows in source that are missing from target
SELECT id, customer_id, amount FROM staging.sales
EXCEPT
SELECT id, customer_id, amount FROM silver.sales;

-- Rows that match exactly between source and target
SELECT id, customer_id, amount FROM staging.sales
INTERSECT
SELECT id, customer_id, amount FROM silver.sales;
```

## 2026-10-12 — Delta Lake: Use liquid clustering instead of partition columns

Liquid clustering (Delta 3.0+) replaces static partitioning. It automatically reorganizes data based on your cluster keys and adapts as query patterns evolve — no more partition strategy regret.

```sql

-- Incrementally cluster existing data
```

## 2026-10-13 — Data Quality: Test for referential integrity at Gold layer

Before writing fact tables, verify all foreign keys resolve to dimension records. Orphaned fact rows (no matching customer/product) cause blank labels in reports and confuse business users.

## 2026-10-14 — PySpark: Use struct columns to group related fields

Instead of many flat columns, group related fields into a struct. This improves schema readability, allows atomic updates, and reduces the number of top-level columns in wide Parquet files.

```python
from pyspark.sql.functions import struct

df = df.withColumn('address', struct(
    col('street').alias('street'),
    col('city').alias('city'),
    col('zip').alias('zip'),
    col('country').alias('country')
)).drop('street', 'city', 'zip', 'country')

# Access: df.select('address.city')
```

## 2026-10-16 — SQL: DATE_TRUNC for consistent time-series grouping

Use DATE_TRUNC to group by calendar periods consistently. It truncates a timestamp to the start of the period — month, week, quarter, year — preventing off-by-one errors from manual date math.

```sql
-- Sales by month
SELECT
  DATE_TRUNC('month', sale_date) AS month,
  SUM(amount) AS total_sales,
  COUNT(*) AS transaction_count
FROM sales
GROUP BY DATE_TRUNC('month', sale_date)
ORDER BY month;
```

## 2026-10-17 — Delta Lake: Shallow clone for testing without data copy

Use SHALLOW CLONE to create a zero-copy clone of a Delta table for testing. It references the same underlying files — no data duplication — and you can write to the clone without affecting the original.

```sql
-- Create a test clone (no data copied)
CREATE TABLE gold.fact_sales_test
SHALLOW CLONE gold.fact_sales;

-- Test your migration on the clone
UPDATE gold.fact_sales_test SET amount = amount * 1.1 WHERE year = 2024;

-- Drop when done
DROP TABLE gold.fact_sales_test;
```

## 2026-10-18 — Data Quality: Profile data before building pipelines

Always profile source data before writing ETL logic. Check: null rates, distinct counts, min/max, value distributions, and referential integrity. Surprises found in profiling are features; surprises in production are incidents.

```python
# Quick profiling with PySpark
df.describe().show()                    # count, mean, stddev, min, max
df.select([F.countDistinct(c).alias(c) for c in df.columns]).show()
df.select([F.sum(F.col(c).isNull().cast('int')).alias(c) for c in df.columns]).show()
```
