## 2026-10-01 — SQL: Index foreign key columns in fact tables

Fact tables join to dimensions on foreign keys. Without indexes on those columns, every join does a full table scan. Add non-clustered indexes on all FK columns in your fact tables.

```sql
-- SQL Server / Azure SQL
CREATE NONCLUSTERED INDEX IX_fact_sales_customer
  ON dbo.fact_sales (customer_id)
  INCLUDE (amount, transaction_date);

CREATE NONCLUSTERED INDEX IX_fact_sales_product
  ON dbo.fact_sales (product_id)
  INCLUDE (amount, quantity);
```

## 2026-10-06 — SQL: Partition elimination is your best optimization

Filtering on a partition column eliminates entire file groups before reading. A query on a 10TB table with date partitioning might read only 27GB for a single month. Always design partition keys around your most common query patterns.

```sql
-- Table partitioned by year, month
-- This query reads ONLY 2024/01 partition files
SELECT SUM(amount)
FROM fact_sales
WHERE year = 2024 AND month = 1;
```

## 2026-10-08 — Data Quality: Reconcile row counts between source and target

After every load, compare row counts between source and destination. A mismatch signals a dropped partition, a failed partial write, or a filter bug. Log the delta and alert on >0.1% variance.

```python
def reconcile(source_count: int, target_count: int, table: str) -> None:
    delta = abs(source_count - target_count)
    pct = delta / source_count if source_count > 0 else 1.0
    if pct > 0.001:
        raise ValueError(
            f'{table}: source={source_count:,}, target={target_count:,}, '
            f'delta={delta:,} ({pct:.2%}) — exceeds 0.1% threshold'
        )
```

## 2026-10-09 — PySpark: Handle skewed joins with salting

When one join key has millions of rows (e.g., a 'null' customer_id), that partition becomes a hotspot. Salt the key by adding a random suffix 0–N, replicate the other side N times, then join and remove the salt.

```python
import random
from pyspark.sql.functions import col, lit, concat, rand, floor

N = 10  # salt factor
salted_fact = fact.withColumn('salt', (rand() * N).cast('int'))\
                   .withColumn('join_key', concat(col('customer_id'), lit('_'), col('salt')))

exploded_dim = dim.crossJoin(
    spark.range(N).withColumnRenamed('id', 'salt')
).withColumn('join_key', concat(col('customer_id'), lit('_'), col('salt')))

result = salted_fact.join(exploded_dim, 'join_key').drop('salt', 'join_key')
```

## 2026-10-11 — SQL: Use EXCEPT and INTERSECT for data reconciliation

EXCEPT and INTERSECT are powerful for reconciliation — find rows in source but not target, or rows that match exactly. Much faster than a NOT EXISTS correlated subquery on large tables.

```sql
-- Rows in source that are missing from target
SELECT id, customer_id, amount FROM staging.sales
EXCEPT
SELECT id, customer_id, amount FROM silver.sales;

-- Rows that match exactly between source and target
SELECT id, customer_id, amount FROM staging.sales
INTERSECT
SELECT id, customer_id, amount FROM silver.sales;
```

## 2026-10-16 — SQL: DATE_TRUNC for consistent time-series grouping

Use DATE_TRUNC to group by calendar periods consistently. It truncates a timestamp to the start of the period — month, week, quarter, year — preventing off-by-one errors from manual date math.

```sql
-- Sales by month
SELECT
  DATE_TRUNC('month', sale_date) AS month,
  SUM(amount) AS total_sales,
  COUNT(*) AS transaction_count
FROM sales
GROUP BY DATE_TRUNC('month', sale_date)
ORDER BY month;
```

## 2026-10-19 — PySpark: Use foreachBatch for streaming-to-Delta upserts

Structured Streaming's native Delta sink only supports append mode. To do upserts (MERGE) from a stream, use `foreachBatch` — it gives you a static DataFrame of each micro-batch to run arbitrary Delta operations on.

```python
def upsert_batch(batch_df, batch_id):
    batch_df = batch_df.dropDuplicates(['event_id'])
    DeltaTable.forPath(spark, output_path)\
      .alias('t')\
      .merge(batch_df.alias('s'), 't.event_id = s.event_id')\
      .whenNotMatchedInsertAll()\
      .execute()

stream.writeStream.foreachBatch(upsert_batch)\
  .option('checkpointLocation', checkpoint_path)\
  .start()
```

## 2026-10-21 — SQL: Use GENERATE SERIES to fill date gaps

Reports with gaps in time series confuse business users. Use GENERATE_SERIES (PostgreSQL/Synapse) or a calendar table to produce all dates, then LEFT JOIN your data — gaps show as 0 instead of missing rows.

```sql
-- Fill daily gaps for a 30-day report
WITH calendar AS (
  SELECT generate_series(
    DATE_TRUNC('day', NOW()) - INTERVAL '30 days',
    DATE_TRUNC('day', NOW()),
    INTERVAL '1 day'
  )::date AS report_date
)
SELECT c.report_date, COALESCE(SUM(s.amount), 0) AS total
FROM calendar c
LEFT JOIN sales s ON s.sale_date = c.report_date
GROUP BY c.report_date
ORDER BY c.report_date;
```

## 2026-10-23 — Data Quality: Use checksums to validate file transfers

When moving large files between storage accounts or cloud regions, always validate with MD5/SHA256 checksums. A corrupted file that passes row count checks but fails checksum is a silent data corruption risk.

```python
import hashlib

def file_checksum(path: str) -> str:
    h = hashlib.md5()
    with open(path, 'rb') as f:
        for chunk in iter(lambda: f.read(8192), b''):
            h.update(chunk)
    return h.hexdigest()

# Compare source and destination checksums
assert file_checksum(source) == file_checksum(dest), 'Checksum mismatch!'
```

## 2026-10-24 — PySpark: Use coalesce instead of repartition when reducing

When reducing partition count, `coalesce(n)` avoids a full shuffle by merging local partitions — much cheaper than `repartition(n)`. Use `repartition` only when you need even distribution or want to increase partitions.

```python
# Reducing partitions — use coalesce (no shuffle)
df.coalesce(10).write.parquet(output_path)

# Increasing partitions or redistributing — use repartition (full shuffle)
df.repartition(200, 'customer_id').write.parquet(output_path)
```

## 2026-10-26 — SQL: Materialized views for expensive aggregations

Repeatedly running the same GROUP BY aggregation on billions of rows is wasteful. Materialize it as a view or table and refresh on a schedule. Power BI and downstream queries read the pre-computed result.

```sql
-- Synapse Analytics / Dedicated SQL Pool
CREATE MATERIALIZED VIEW gold.mv_monthly_sales
WITH (DISTRIBUTION = HASH(customer_id))
AS
SELECT
  DATE_TRUNC('month', sale_date) AS month,
  customer_id,
  SUM(amount) AS total_sales
FROM silver.sales
GROUP BY DATE_TRUNC('month', sale_date), customer_id;
```

## 2026-10-29 — PySpark: Filter before join, not after

Always apply `.filter()` on DataFrames before joining them. Spark pushes filters down, but explicit pre-filtering reduces shuffle size and speeds up joins significantly.

```python
# Good — filter first, then join
active = customers.filter(col('status') == 'active')
result = orders.join(active, 'customer_id')

# Bad — filters after join
result = orders.join(customers, 'customer_id').filter(col('status') == 'active')
```

## 2026-10-30 — SQL: Use window functions instead of self-joins

Self-joins to compute running totals or previous values are slow and hard to read. Replace them with window functions — they run in a single pass over the data.

```sql
-- Running total per customer
SELECT customer_id, amount,
  SUM(amount) OVER (
    PARTITION BY customer_id
    ORDER BY transaction_date
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_total
FROM transactions;
```
