# Daily Data Engineering Tips — August 2026


## 2026-08-01 — PySpark: Broadcast small dimension tables

For dimensions under ~100MB, broadcast them to all executors to avoid a shuffle join. Spark may auto-broadcast based on `spark.sql.autoBroadcastJoinThreshold`, but explicit hints are more reliable.

```python
from pyspark.sql.functions import broadcast

# Explicit broadcast hint
result = fact_df.join(
    broadcast(dim_product),
    'product_id'
)
```

## 2026-08-02 — Delta Lake: Schema enforcement protects your pipeline

Delta Lake enforces schema by default — writes with unexpected columns fail loudly. Use `mergeSchema=true` only at Bronze where sources evolve. Silver and Gold should fail on schema mismatches so you catch upstream changes early.

```python
# Bronze — allow schema evolution
bronze_df.write.format('delta')\
  .option('mergeSchema', 'true')\
  .mode('append').save(bronze_path)

# Silver — enforce strictly (default, no option needed)
silver_df.write.format('delta').mode('append').save(silver_path)
```

## 2026-08-03 — SQL: Use EXPLAIN ANALYZE before optimizing

Never guess at performance bottlenecks — run EXPLAIN ANALYZE to see the actual execution plan and row estimates. Look for seq scans on large tables, bad row estimates, and nested loop joins on large datasets.

```sql
-- PostgreSQL / Synapse
EXPLAIN ANALYZE
SELECT c.customer_name, SUM(s.amount)
FROM sales s
JOIN customers c ON s.customer_id = c.customer_id
WHERE s.sale_date >= '2024-01-01'
GROUP BY c.customer_name;
```

## 2026-08-04 — Data Quality: Row count checks catch silent failures

Always assert row count > 0 after every pipeline stage. Silent empty DataFrames that pass through to Gold corrupt downstream reports with no error message. A simple count check costs milliseconds.

```python
def assert_not_empty(df, stage: str) -> None:
    count = df.count()
    if count == 0:
        raise ValueError(f'{stage} produced 0 rows — check upstream source')
    print(f'{stage}: {count:,} rows OK')
```

## 2026-08-05 — Microsoft Fabric: Partition your Lakehouse tables by date

Always partition large Delta tables by date (year/month or date). Power BI and Spark both prune partitions automatically when date filters are applied, cutting scan size from 100% to just the requested partitions.

```python
df.write.format('delta')\
  .partitionBy('year', 'month')\
  .mode('overwrite')\
  .save('Tables/gold/fact_sales')
```

## 2026-08-07 — SQL: Avoid SELECT * in production queries

SELECT * reads all columns — even ones you don't need. On columnar formats (Parquet, Delta), this defeats column pruning and reads 3–10x more data than necessary. Always name your columns explicitly.

```sql
-- Bad — reads all columns from Parquet
SELECT * FROM gold.fact_sales WHERE year = 2024;

-- Good — only reads 4 columns from disk
SELECT sale_id, customer_id, amount, transaction_date
FROM gold.fact_sales
WHERE year = 2024;
```

## 2026-08-08 — Azure Data Factory: Use variables for dynamic pipeline dates

Hardcoding dates in ADF queries breaks on re-runs and backfills. Use pipeline parameters + system variables like `@utcNow()` and `@formatDateTime()` so pipelines work for any run date.

```sql
@formatDateTime(pipeline().parameters.run_date, 'yyyy-MM-dd')

-- Dynamic source query
SELECT * FROM dbo.Orders
WHERE OrderDate = '@{formatDateTime(pipeline().parameters.run_date, 'yyyy-MM-dd')}'
```

## 2026-08-09 — Delta Lake: Use MERGE for idempotent upserts

MERGE (Delta's upsert operation) is idempotent — safe to re-run if a job fails. It updates existing records and inserts new ones in a single atomic operation, replacing the delete-then-insert anti-pattern.

```python
DeltaTable.forPath(spark, target_path)\
  .alias('t')\
  .merge(source_df.alias('s'), 't.id = s.id')\
  .whenMatchedUpdateAll()\
  .whenNotMatchedInsertAll()\
  .execute()
```

## 2026-08-10 — Data Quality: Track null rates per column at Silver layer

Compute null rate for every column at Silver ingestion. Set a threshold (e.g., >5% = fail). Null spikes indicate upstream schema changes or source system issues — catch them before they reach Gold.

```python
def null_rates(df) -> dict:
    total = df.count()
    return {
        col: df.filter(F.col(col).isNull()).count() / total
        for col in df.columns
    }
```

## 2026-08-11 — PySpark: Repartition before writing to avoid small files

Spark writes one file per partition. If your DataFrame has 200 partitions but only 1M rows, you get 200 tiny files — the small file problem. Coalesce or repartition before writing.

```python
# Target ~128MB per file
# For 10GB of data → 80 partitions
df.coalesce(80)\
  .write.format('delta')\
  .mode('append')\
  .save(output_path)
```

## 2026-08-12 — SQL: Index foreign key columns in fact tables

Fact tables join to dimensions on foreign keys. Without indexes on those columns, every join does a full table scan. Add non-clustered indexes on all FK columns in your fact tables.

```sql
-- SQL Server / Azure SQL
CREATE NONCLUSTERED INDEX IX_fact_sales_customer
  ON dbo.fact_sales (customer_id)
  INCLUDE (amount, transaction_date);

CREATE NONCLUSTERED INDEX IX_fact_sales_product
  ON dbo.fact_sales (product_id)
  INCLUDE (amount, quantity);
```

## 2026-08-14 — Data Quality: Use Great Expectations for automated data contracts

Define data expectations as code — column types, value ranges, referential integrity. Run them in your pipeline as a quality gate. Failed expectations block the write and alert the team before bad data reaches consumers.

```python
import great_expectations as gx

context = gx.get_context()
suite = context.add_expectation_suite('silver.sales')
suite.add_expectation(
    gx.expectations.ExpectColumnValuesToBeBetween(
        column='amount', min_value=0, max_value=1_000_000
    )
)
```
